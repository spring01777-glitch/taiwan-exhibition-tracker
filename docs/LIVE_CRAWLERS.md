# 演唱會／脫口秀自動擷取來源

`scripts/crawl_live_sources.py` 每日台灣09:00由同一 workflow 執行，之後 `update_live_events.py` 重建 `data/concerts.json`、`data/comedy.json`。只納入沒有 API、但有公開結構化資料或公開頁面、且 robots.txt 允許的低風險來源。

| 來源 | 讀取內容 | 類別 | 限制 |
| --- | --- | --- | --- |
| 卡米地 `comedyclub.kktix.cc` | 主辦公開 `events.json`（最新100筆） | 脫口秀 | 多日總覽頁排除；標題／簡介沒有明確單口、脫口秀字樣者列待分類，不發布 |
| 薩泰爾 `strnetwork.kktix.cc` | 主辦公開 `events.json` | 脫口秀 | 同上；地址沒有縣市的英文場地列待分類 |
| 臺北小巨蛋 `arena.taipei` | 「已公開(售票/派票)活動」政府開放資料 JSON | 演唱會 | 場次取開演時間，不取入場／結束時間；售票系統只記名稱 |
| 北流 `tmc.taipei` | 「最近活動」公開頁＋各活動頁 | 演唱會 | 只讀標記為演唱會／中心自辦／合辦的卡片；超過兩天的日期區間不推定場次 |
| OPENTIX `opentix.life` | 公開 sitemap＋活動頁 schema.org Event（每場一筆） | 演唱會、脫口秀 | 每個台灣日曆日最多100次活動頁讀取嘗試，含失敗與同日重跑；兩種類別共用進度；新URL優先，已讀活動不重抓。詳見下方增量規則。 |

不自動化：拓元、ibon、年代、寬宏（條款或防機器人機制限制）、KKTIX 總站（Cloudflare 阻擋）。這些來源仍用人工核對匯入（`--reviewed-input`／`--canonical-input`）。

## 安全與資料規則

- 只發 HTTPS GET 到登記的固定主機；拒絕跨主機轉址、帳密網址；單次回應上限5MB。
- 每個來源先讀 robots.txt（404 視為無限制），不允許的網址不讀。每次請求間隔1.2秒。
- 分類沿用 `live_sources.classify`；課程、音樂劇、歌劇（含歌仔戲團名）、相聲、即興等排除，證據不足列「待分類」，不發布。
- 已過期場次不新增。來源本次沒列出的舊資料保留，不推定取消。
- 與既有人工核對紀錄同一活動（相同ID，或標題正規化相同且日期重疊）時，只更新標題外的場次與網址；人工核對的票價、開賣時間、備註、購票連結保留。
- 單一來源失敗、無效紀錄超過20%、或納入數比上次自動更新少一半以上（上次至少6筆）時，該來源保留最後成功快照並標示錯誤；其他來源照常更新。workflow 仍部署保留資料，最後以失敗結束提醒。

## 演唱會類型

`live_sources.concert_genre` 依標題與演出者把演唱會分為：流行／搖滾演唱會、古典／室內樂、國樂／傳統、合唱／聲樂、爵士、管樂、其他音樂會（只寫「音樂會」而無其他線索）。規則依序比對，先中先用；只用公開標題，不讀簡介。演唱會頁有「類型」篩選，卡片顯示類型標籤。分類是關鍵字推定，可能有誤，不代表主辦方官方分類。

## 場館展覽（松菸、華山、駁二）

`update_venue_sources.py` 使用下方統一增量規則；單筆缺標題或地點的頁面保留待辦，不冒填內容。明確單日日期按單日活動處理；常設、長期或缺明確結束日期的活動不自動判定過期。來源中途失敗保留原公開快照與完成進度。

## 本機執行

```bash
python scripts/crawl_live_sources.py                 # 全部來源
python scripts/crawl_live_sources.py --source tmc    # 單一來源
python scripts/update_live_events.py                 # 重建公開 JSON
python -m unittest tests.test_live_crawl -v          # 離線測試，不連網
```


## 統一的新活動增量規則

OPENTIX、松菸、華山、駁二皆只讀首次出現的活動URL，不再輪巡已讀活動。每個來源各有台灣日曆日100次活動詳情嘗試上限，含失敗與同日重跑；OPENTIX的演唱會與脫口秀共用同一額度。robots、政策與清單索引的少量請求另計。沒有100筆新活動時不為湊數重抓舊活動。

- 已有成功資料作為基線，不清空重抓。每次活動請求前儲存當日嘗試紀錄；失敗的URL同日不再重試，次日續抓。首次遷移因舊版無當日完整帳本，保守保留當天額度，次日開新額度。
- 每天成功讀一次公開索引，URL去重，新增項目與未完成佇列交錯，避免順序移動、重跑或新活動持續加入使舊進度遺失。已讀URL暫時消失再出現不重抓。上限指活動頁，不是場次數或成功納入數。
- OPENTIX讀單一公開 `otWebSitemap.xml` 的 `/event/數字` URL；不以ID或 `lastmod` 假定上架先後。三館讀原已核准的公開展演清單；華山不翻帶查詢參數的受限分頁。**公開可見順序不保證發布時間排序，不能宣稱取得全站最新100筆或完整目錄。**
- 松菸讀展演清單卡片（排除展演攻略）；華山讀展演首頁卡片；駁二以既有瀏覽器讀公開頁面正常載入的活動，不自行呼叫內部API、不抓歷史列表。各來源robots、隱私政策指紋、1.2秒限速及固定主機限制維持。
- 三館進度儲存於 `data/venue-crawl-state.json`，成功取得但尚未公開的事實也保留，來源中途失敗不替換最後成功快照。OPENTIX進度繼續使用 `data/live-sources/crawl-state.json`。正常失敗仍提交狀態；整台執行器強制終止而未提交的資料無法跨執行器復原，不應清空額度或狀態。
- 已知結束日期早於台灣今天的展覽從預設展示移出，歷史資料保留；結束當天仍展示。頁面在台灣午夜或背景分頁恢復時更新判斷。結束日期未明（例如常設、長期或只有起日）保留並標示待確認，不推定過期，也不冒稱適用特定日期。
- **只讀新活動的代價：已收錄活動之後改期、加場、改票價或取消，不再主動更新；出發前仍需查官方。** 首次讀取若有明確取消證據仍照原解析保存。不保證即時，也無法發現未進入核准公開索引的活動。
